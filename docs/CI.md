# GitHub CI/CD

Репозиторий: https://github.com/Dlzxn/code-pet. Workflow: `.github/workflows/ci.yml`.

## Получить тестовую сборку

После отправки исходников открой **Actions → Build and test → последний успешный запуск → Artifacts**. Скачай `code-pet-<commit SHA>`, распакуй внешний архив артефакта. Внутри будет устанавливаемый `code-pet-0.3.0.zip`; его распаковывать не нужно. Установи через **Plugins → Install Plugin from Disk**.

В `reports-<SHA>` находятся логи и предпросмотры. `ui-preview.png` и `pets-gallery.png` созданы headless, они не подтверждают реальное поведение PyCharm.

Push в main, PR и workflow_dispatch запускают автоматические проверки. Перед тестами устанавливаются Python 3.13, Java 25 и точный Linux SDK PyCharm 2026.3 build 263.7307.206. Архив SDK скачивается с JetBrains и проверяется по SHA256 издателя. SDK кешируется, но не публикуется в репозитории или артефактах плагина. Первое скачивание будет дольше последующих прогонов.

Если URL/контрольная сумма SDK недоступны, workflow завершится с ошибкой, а не незаметно возьмёт другую версию. Фактическая загрузка в GitHub пока требует первого облачного прогона. Обновлять SDK pin нужно одновременно в `sdk.py`, `scripts/install_ci_sdk.py`, ключе кеша workflow и `plugin.xml`.

## Выпуск версии

1. Пройди ручной сценарий из TESTING.md на конкретном commit SHA.
2. Измени версию в `resources/META-INF/plugin.xml` и запись в CHANGELOG.md. Имя ZIP вычисляется из дескриптора.
3. После зелёного main создай и отправь тег соответствующей версии, например `v0.3.0`.
4. Успешный tagged workflow создаст **draft Release**, приложив ZIP. Проверь содержимое и опубликуй черновик вручную, когда он готов.

Workflow не устанавливает ZIP пользователю и не публикует ничего в JetBrains Marketplace. Основная проверка имеет `contents: read`; отдельная release job получает `contents: write` только для черновика релиза. Пользовательские токены/SSH-ключи в Actions secrets для этого не нужны, используется встроенный `GITHUB_TOKEN`.

## Границы CI

CI подтверждает сборку и headless-проверки. Оно не подтверждает, что пользовательские окна IDE не перекрываются, что любая конфигурация inlay hints безопасна, или что все клики ведут себя правильно на Retina. Для этого нужна ручная приёмка.

Первое выполнение workflow необходимо просмотреть: доступность Actions в репозитории, реальные URL SDK, среда Linux и права создания draft release ещё не проверяются одним локальным запуском.
