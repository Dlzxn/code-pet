# Архитектура

Плагин не использует внешние библиотеки, LLM и сеть. Java 25, Swing и Java2D, локальные JAR-файлы PyCharm SDK.

## Состояние

`PetState` — application service, `PersistentStateComponent<PetCollection>`, storage `code-pet.xml`. `PetCollection` хранит профили, активный ID и обезличенные максимумы файлов. `PetModel` хранит XP, статистику, настройки и одежду одного персонажа. Каталог анатомии/палитр/слотов — `PetCatalog`.

`getState()` возвращает отдельный снимок списков и профилей, чтобы XML-сериализация не обходила изменяемую UI коллекцию. Примитивные/строковые поля копируются; исходный код не сохраняется. При загрузке восстанавливаются валидные диапазоны, отсутствующие/дублирующиеся ID и активный выбор. Старые корневые поля 0.1/0.2 переносятся в единственный начальный профиль; устаревший уход игнорируется.

Штатная периодичность записи на диск определяется IntelliJ Platform. «Автосохранение» означает отсутствие отдельной кнопки сохранения, а не синхронный flush XML при каждом клике. Принудительное завершение процесса между сохранениями может потерять последние изменения.

## Учёт кода

`PetActivityListener` фильтрует контекст команды/фокуса. `PetEligibility` проверяет исходный файл и относительные пути проекта. `PetCodingTracker` — project service с одним одноразовым Swing-таймером, debounce 650 мс и максимум 24 ожидающими документами. Чтение метрик ограничено файлами до 500 000 UTF-16 единиц.

Перед началом batch фиксируются исходные метрики и ID владельца правок. После паузы `PetMetrics` считает непробельный объём и подходящие строки; `PetCollection.record()` сравнивает их с сохранёнными максимумами и передаёт рост в `PetModel.earn()`. Переключение профиля не перенаправляет уже сделанные правки другому питомцу. Неоднозначное внешнее изменение отменяет ожидающую награду и повышает базовые максимумы без XP.

VFS-расширение `PetFileListener` принимает созданные через команду IDE файлы проекта, исключает directories/refresh/служебные пути и увеличивает счётчик автоматических перекусов. Этот сигнал не даёт XP. У каждого проекта нет отдельной дублирующей VFS-подписки: слушатель один на приложение.

Метрики не являются парсером или защитой от любого способа накрутки. Имена и абсолютные URL файлов хешируются SHA256; в сохранении остаются только хеш и числовые максимумы. Хеш пути не гарантирует анонимность против угадывания известных путей.

## Отрисовка и жизненный цикл

`PetStartup` реализует актуальный `ProjectActivity` из SDK через простой несуспендящий Java bridge и запускает `PetRoaming` в EDT.

`PetBehavior` и `PetDialogue` не имеют доступа к XP. Автономная машина состояний управляет сценой, прогрессом, направлением и наведением. Переходы ухода ведут в скрытое состояние, затем в одну из сцен появления. Анатомия и надетые предметы рисуются в `PetPainter`; один и тот же рисунок используется в панели и поверх редактора.

`PetSafeArea` получает прямоугольники запрещённых участков и ищет целиком свободную полосу. `PetRoaming` строит эти участки из видимых непустых строк с отступом 48 px и каретки. Переносы занимают всю соответствующую ширину; при слишком большом числе логических строк показ отменяется. Геометрия кешируется до 200 мс, но изменение текста, каретки, viewport или профиля инвалидирует её раньше. Проверка перед рисованием запрещает старые кадры после редактирования/прокрутки.

Наложенный `JComponent` в `PALETTE_LAYER` прозрачный, без фокуса, с `contains() == false`. Системный glass pane не заменяется. Глобальная позиция мыши считывается без подписки, перехватывающей события редактора. При закрытии проекта `dispose()` останавливает таймер и удаляет компонент; фоновые документы не удерживаются после освобождения сервиса. При отсутствии места/неактивном окне частота проверок снижается.

`PetToolWindow` владеет отдельным таймером панели через `Content.setDisposer()`. UI получает коллекцию через supplier: это позволяет тестировать настоящие кнопки/компоненты headless без запуска IDE. `PetUi` меняет оформление только собственных компонентов, без глобального `UIManager.setLookAndFeel`.

## Сборка и границы проверки

`sdk.py` единообразно находит SDK macOS/Linux. `build.py` очищает только `build/classes`, компилирует production Java и упаковывает JAR/ZIP. Версия ZIP берётся из `plugin.xml`. `scripts/verify_package.py` проверяет ZIP, XML, классы расширений и содержимое JAR. Отдельные тестовые классы в плагин не включаются.

Автотесты SDK используют адаптеры, а не полноценный `ApplicationImpl`. Полная интеграция с редактором, потоками платформы, плагинным classloader и сохранением IDE проверяется вручную в изолированном профиле. IntelliJ Plugin Verifier и инструмент покрытия ещё не подключены.
