# Архитектура

Java 25, Swing и Java2D, SDK PyCharm 2026.3 build 263.7307.206. Во время работы плагин не использует сеть, LLM и внешние библиотеки.

## Состояние и опыт

`PetState` — application service, `PersistentStateComponent<PetCollection>`, storage `code-pet.xml`. `activeId` обозначает профиль, выбранный для редактирования; `activeIds` — одновременно включённых спутников. Новый профиль включается без выключения прежних. Старое сохранение мигрирует в один включённый профиль. `activeIdsInitialized` отличает прежний формат от намеренно пустого списка; теперь можно убрать последнего спутника и сохранить пустой экран. `behindText` и `keyboardGames` общие; образы, XP, пауза XP и анимации индивидуальны.

`getState()` возвращает отдельный снимок списков, профилей и максимумов файлов. Координаты, текущая игра и сигналы запуска transient. При загрузке нормализуются диапазоны и ID, сохраняется старый прогресс. Запись выполняет IDE с обычной периодичностью; отдельной кнопки сохранения нет.

`PetActivityListener` и `PetEligibility` фильтруют локальные исходники, команды и фокус. `PetCodingTracker` откладывает подсчёт метрик до 650 мс покоя, хранит не более 24 документов по 500 000 UTF-16 единиц. До batch фиксируются исходные метрики и список включённых получателей. `recordFor()` один раз повышает общие максимумы файла и выдаёт полный прирост каждому уникальному существующему получателю. Отключение/включение после начала batch не перенаправляет старые правки. Пауза XP обновляет максимум без накопления награды.

`PetMetrics` использует объём и префиксы комментариев, а не парсер языка. URL файлов хешируются SHA256; сохраняются хеш и числовые максимумы. `PetFileListener` подписан один раз на приложение, новый подходящий файл увеличивает счётчик перекусов включённых питомцев, без XP. Внешние/bulk/undo изменения исключаются.

## Ввод и жизненный цикл

`PetStartup` запускает project service `PetRoaming` в EDT. У него один Swing Timer 40 мс, AWT observer мыши и ранний `IdeEventQueue.addPreprocessor` для клавиатуры. Клавиши наблюдаются до обработки шорткатов PyCharm; обработчик всегда возвращает false. Отдельный Disposable снимает preprocessor при закрытии проекта, AWT observer удаляется, таймер останавливается. Единственный публичный конструктор сервиса принимает Project; тестовый источник событий подставляется при start. В неактивном окне, тихом режиме и при отсутствии подходящего контекста сцена приостанавливается, удержание Delete сбрасывается.

Enter/Tab/Delete обрабатываются только при фактическом фокусе в content component выбранного основного невьюерного редактора (source события используется при отсутствии focus owner), без Ctrl/Meta/Alt/Shift. События никогда не consume и не переназначают действия. Release Delete принимается независимо от текущего фокуса. `PetPlayInput` держит serial игрушек, антиавтоповтор (300 мс Enter, 1 с Tab), порог кресла 650 мс и 4 с после отпускания. Для наведения в памяти остаётся последняя позиция мыши; текст клавиш и координаты не сохраняются на диск.

`PetExecutionListener.processStarting` даёт transient сигнал Run. Для распознанных тестовых конфигураций завершение даёт косметическую реакцию всем включённым профилям. Код завершения не является деревом тестовых assertion-результатов.

## Сцена и порядок рисования

`PetPlayScene` хранит отдельный Buddy/behavior для каждого включённого ID и один общий `PetBall`. Кадры передаются painter как неизменяемые списки Actor/BallFrame в EDT. Исключённые профили удаляются из runtime map. Приоритет: общий диван Run → разбег → кресло → шарик → погоня за мячом → автономная история. Enter, Tab и удержание Delete отменяют диван, чтобы он не блокировал игровые клавиши.

`PetEditorBackground` создаёт один RangeHighlighter на весь документ без TextAttributes, greedy в обе стороны. Его CustomHighlighterRenderer возвращает **AFTER_BACKGROUND**: SDK рисует питомцев после фона, перед текстовыми glyph. Плагин не подменяет Document, EditorPainter, keymap, selection и undo. При смене редактора/отключении/закрытии highlighter освобождается. На кадре перерисовывается пересечение видимого viewport с объединением старых и новых границ рисунка.

Для нижней свободной области Project, дивана Run и короткого разбега есть один прозрачный полнооконный `Surface` на PALETTE_LAYER. Он не получает фокус и возвращает `contains()==false`, пропуская мышь. На каждом движении меняются координаты рисунка внутри него, его Swing bounds остаются стабильными. Это устраняет одну из причин прежнего мерцания; реальный Retina/UI scale проверяется вручную.

Project используется, только если видимый JTree имеет не менее 125 px свободного места под последней строкой. Раз в 22 с меняется распределение спутников между редактором и Project. Поиск Run читает видимые tooltip/accessible name и использует верх справа при отсутствии распознанной кнопки. Скрытые панели не открываются.

## Игры и истории

`PetBall` работает в текущем видимом прямоугольнике редактора: гравитация, отражение от четырёх границ, затухание и максимальное время жизни 25 с. Шаг ограничен 60 мс. Новый Enter заменяет общий мяч. После 650 мс оценки Buddy преследует цель; вид задаёт импульс прыжка, джетпак заменяет его управляемым полётом.

Tab задаёт подъём шарика с двумя синусоидами бокового ветра, верёвкой и нарисованными порывами. Подъём завершается сверху или через 14 с. Удержание Delete использует отдельную позу CINEMA, масштаб 1,8, кресло, попкорн и взгляд влево вверх. Отключение игр прекращает текущие игрушки/кресло. Настройка присутствия под текстом управляет только автономными прогулками; включённые игры независимо создают временный фоновой renderer. При отсутствии включённых питомцев игры не рисуются.

`PetBehavior`, `PetStories`, `PetSpeciesScenes`, `PetChores` и `PetPainter` отвечают за последовательности и предметы. По 12 историй у 24 видов. `PetDialogue` даёт редкие реплики, `PetRunPhrases` — по 12 вариантов с именем и особенностями вида. В UI нет обязательного выбора занятий. Через 45 с отсутствия чаще выбирается уборка; возможность увеличения 1,6 выбирается с вероятностью .28 после завершённой истории. История, прерванная игрой, временно приостанавливается.

`PetHome` и находки основаны на уровнях 2–7. Получение подарка однократное; вещи не заменяют выбранную одежду. Счётчик историй сохраняется, точный этап — нет. `PetExploration`, `PetSafeArea`, `PetScenePlacement`, `PetMotion` остаются вспомогательными алгоритмами с проверками; текущая сцена использует фоновые координаты.

## Сборка и границы проверки

`build.py` собирает production-классы и ZIP с версией из plugin.xml, тесты в дистрибутив не входят. `tests/run.py` компилирует и запускает три Java-набора, `--compile-only` не исполняет их. `scripts/check.py` дополнительно запускает Python-проверки и проверяет упаковку.

`scripts/publish.py` проверяет main и SSH origin, добавляет исходники, коммитит при изменениях и отправляет обычным push. Тесты запускает существующий GitHub workflow; скрипт не ждёт CI. Он не использует force и останавливается при ошибках Git.

SDK-адаптеры проверяют сервисные границы и paint hook, но не заменяют реальный PyCharm. Inlay hints, folding, selection, Retina, toolbar и lifecycle при нескольких окнах требуют ручной приёмки. Plugin Verifier и инструмент покрытия не подключены.

## Диван и всплывающие настройки 0.7

`PetLounge` рассчитывает ряды дивана, места всех включённых спутников и телевизор в правом верхнем углу окна. Мебель рисуется общим Surface до/после персонажей. Пожелание отображается одной общей репликой. Наведение проверяет тела персонажей, не телевизор и не пустой прямоугольник сцены. Оно запускает общий разбег за .65–1 секунду; после приземления восстанавливается позиция в текущей истории. На 10 секунд после разбега исключается мгновенный перенос в Project. Без наведения диван скрывается через 12 секунд.

`PetPanel` показывает статус, кнопки «Выпустить в редактор»/«Убрать с экрана», коллекцию и подсказку. `PetPreferences` открывается в отдельном немодальном JDialog с ID конкретного персонажа. Стрелки основного окна не перенаправляют правки другого персонажа. Повторное открытие поднимает существующее окно; Escape/«Готово» закрывают его, освобождая таймер. Закрытие tool window content закрывает все связанные диалоги.
