# Code Pet

Личный фоновый компаньон для PyCharm. Пиши код — активный питомец развивается; сам появляется, исследует свободное место и занимается своими делами. Уход, голод и обязательные действия отсутствуют.

**Текущая версия: 0.3.0.** Совместимость: PyCharm 2026.3, ветка 263; сборка и тесты используют SDK **263.7307.206** и Java 25. Плагин пока предназначен для личного использования и ручной проверки, без публикации в Marketplace.

## Коллекция и внешний вид

- 24 вида: кот, пёс, лис, кролик, панда, медведь, коала, енот, хомяк, мышь, белка, ёж, сова, пингвин, цыплёнок, дракон, динозавр, черепаха, лягушка, аксолотль, летучая мышь, привидение, робот и слайм.
- Можно создавать несколько питомцев. Активен ровно один; он находится в центре карточки, стрелки переключают активного питомца по кругу.
- У каждого свой XP, имя и образ. Смена питомца не переносит опыт между ними.
- 16 цветов для основного окраса, вторичного цвета, глаз и аксессуаров.
- Настройка узора, формы глаз, хвоста и характера.
- 26 носимых аксессуаров в независимых слотах: головной убор, очки/маска, украшение на шее, плащ/рюкзак/крылья/джетпак. Косметика доступна без обязательного гринда.
- Изменения внешности, имя, настройки, коллекция и выбранный питомец сохраняются автоматически средствами IDE.

## Фоновая жизнь

Каждый вид поддерживает общую библиотеку **36 сцен**, адаптированных к его рисунку: портал, коробка, выглядывание, спуск на зонтике, прогулка, бег, прыжки, крадущаяся походка, движение назад, отдых, наблюдение, медленное моргание, потягивание, умывание, отряхивание, вращение, кувырок, танец, ловля хвоста, мяч, светлячок, книга, ноутбук, перекус, чай, зевок, приветствие, сердечко, звёзды, парение, прятки в коробке, падение в норку, телепортация, исчезновение, исследование закулисья и цветок. Это общие сценарии, а не 864 отдельно нарисованные анимации.

Питомец по умолчанию значительно меньше персонажа в панели. При наведении жмурится и приостанавливает движение. Наложенный рисунок не забирает фокус и пропускает клики редактору. Редкие реплики рисуются рядом с ним; их можно отключить. Ни звуков, ни обязательных уведомлений, ни отправки кода в сеть.

Рисунок размещается **только внутри активного текстового редактора PyCharm**, в проверенной пустой области у края. Алгоритм оставляет 48 пикселей отступа от видимых непустых строк и дополнительное пространство вокруг каретки. Он ищет безопасную полосу для всего движения, включая реплики и предметы. Если места нет, питомец скрывается. Скроллинг/изменения текста блокируют отрисовку старого положения до перерасчёта. Рабочий стол macOS и другие приложения не затрагиваются.

Прогулки продолжаются при закрытой панели. Действие **Code Pet: показать питомца в редакторе** доступно через `⌘⇧A`. Анимацию, прогулки и реплики можно отключить независимо от XP.

## Прокачка

- **+2 XP** за новую учитываемую строку с **более чем 10 непробельными символами**.
- **+5 XP** за каждые **100 новых непробельных символов**. Остаток до следующей сотни сохраняется у питомца.
- Два вида наград суммируются. Например, 200 новых символов на трёх подходящих строках дают 16 XP.
- Новый файл в проекте запускает **автоматический перекус**, не требует кормления и сам по себе XP не даёт.
- Поглаживания, игры, время и случайные действия опыта не дают.
- Следующий уровень стоит `100 × текущий уровень`: 100 XP для уровня 2, ещё 200 для уровня 3, ещё 300 для уровня 4. Накопленный XP не тратится.

Учитывается рост объёма файла относительно его ранее достигнутых максимальных показателей. Удалить и заново ввести тот же объём, переключить питомца или перезапустить IDE для повторной награды нельзя. Существующий текст при первом редактировании становится базовой точкой без ретроактивного XP. Пауза не копит отложенную награду.

Это понятная локальная механика, а не оценка качества кода: замена фрагмента на фрагмент той же длины может не дать XP; большие вставки подходят под пропорциональное начисление. Отдельные строки комментариев по префиксам `#`, `//`, `/*`, `*`, `--` и пробелы исключаются; полноценного синтаксического разбора нет. Строки многострочных строковых литералов и некоторые виды комментариев могут считаться кодом. Это ограничение документировано, а не защита от любой накрутки.

Правки сканируются после паузы во вводе около 650 мс, в локальных исходных файлах проекта с фокусом основного редактора. Консоль, undo/redo, фоновые и bulk-изменения, `.idea`, `.git`, зависимости и результаты сборки исключаются. Файлы больше 500 000 UTF-16 единиц не учитываются. Хранится до 5000 обезличенных хешем записей о максимумах файлов; исходный код в сохранение не записывается.

## Быстрый запуск

Из корня проекта на macOS:

```sh
python3 run_ide.py
```

Сначала закрой прежнюю тестовую IDE. Скрипт соберёт плагин и запустит установленный PyCharm с отдельными настройками, плагинами, логами и тестовым проектом в `build/sandbox`. Основной профиль IDE не изменяется. Данные тестового профиля сохраняются между запусками. Открой `example.py`: при наличии безопасного места питомец появится автоматически. Панель: **View → Tool Windows → Code Pet**, либо поиск `Code Pet` через `⌘⇧A`.

Первый запуск отдельного профиля может потребовать настройки или авторизации PyCharm. Не заменяй JAR при работающей тестовой IDE.

## Сборка, проверки и установка

```sh
python3 scripts/check.py
```

Команда запускает проверки Python, компилирует плагин, выполняет проверки Java и SDK-адаптеров, проверяет упаковку и сохраняет отчёты в `build/reports`. Отдельная сборка: `python3 build.py`.

Готовый файл: **`dist/code-pet-0.3.0.zip`**. В основном PyCharm выбери **Settings → Plugins → шестерёнка → Install Plugin from Disk…**, укажи ZIP без распаковки и перезапусти IDE. [Инструкция JetBrains](https://www.jetbrains.com/help/pycharm/managing-plugins.html).

Локальная сборка не скачивает зависимости, использует библиотеки установленной IDE. Другой SDK задаётся через `PYCHARM_HOME` (Contents на macOS или корень распакованной IDE на Linux). Версия SDK проверяется строго. JDK берётся из SDK, при его отсутствии используется `JAVA_HOME`.

## GitHub CI/CD

Workflow `.github/workflows/ci.yml` подготовлен для push в `main`, pull request и ручного запуска:

1. Linux-раннер устанавливает Python 3.13 и Java 25.
2. Загружает точный SDK PyCharm 2026.3, сверяет SHA256 издателя и build; повторно использует кеш.
3. Выполняет ту же команду `python scripts/check.py`.
4. При успехе прикладывает устанавливаемый ZIP; отчёты и PNG-предпросмотры сохраняются и при ошибках, если были созданы.
5. Тег `v*` после успешной сборки создаёт черновик GitHub Release с ZIP. Публикация Marketplace не выполняется.

Первый облачный прогон ещё необходимо подтвердить после отправки проекта в репозиторий. Локальные успешные тесты не означают, что Actions уже запущен или что реальная загрузка SDK в CI проверена. [Как скачивать сборку и выпускать версии](docs/CI.md).

## Проверка качества и ограничения

Проверки покрывают XP и уровни, ограничения чисел, коллекцию и карусель, автосохранение полей UI, XML и перенос сохранений 0.1/0.2, безопасные области, сценарии, наведение, все виды и аксессуары, пропуск кликов на уровне Swing, SDK-адаптер учёта правок и остановку таймеров. Проверяются также инструменты сборки и скачивания SDK без настоящей сетевой загрузки.

В `build/reports` создаются `summary.json`, логи, `pets-gallery.png`, `ui-preview.png` и тестовый XML. Это реальные headless-отрисовки компонентов, **не скриншоты PyCharm**.

**Интеграция 0.3.0 в настоящую IDE пока не подтверждена.** Из среды агента запуск IDE блокируется запретом локальных сокетов. Настоящие фокус, мышь, окна, масштабирование, folding, inlay hints и смена вкладок требуют ручной проверки. Консервативное скрытие предпочтительнее наложения на код. Не обещаем «абсолютную идеальность» или полное отсутствие ошибок по результатам одних автотестов.
